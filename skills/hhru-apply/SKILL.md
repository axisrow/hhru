# hhru-apply — воркфлоу отклика

Отклик на вакансии hh.ru — **write-команда к hh.ru**, самая safety-critical.
Строго соблюдай порядок: сначала сухой прогон, потом боевой — и только с
подтверждением пользователя.

Этот skill описывает один типовой workflow, но не меняет общий принцип CLI:
команды — примитивы, а не отдельная готовая команда под каждую пользовательскую
задачу. Нестандартные задачи собирай поэтапно из существующих команд; общий
пример с редактированием разделов резюме приведён в `skills/hhru/SKILL.md`.

## Разрешение браузера в Codex

Все браузерные шаги этого workflow (`list-resumes`, `probe`, dry-run и боевой
`apply`, при необходимости `login`) с первого запуска выполняй с
`sandbox_permissions=require_escalated`. Не запускай их сначала в sandbox и не
используй `--headless` как замену разрешению: Chromium требует разрешённого пути
в обоих режимах. Обычный локальный `whoami` разрешения браузера не требует.

Elevated-разрешение — только право запустить Chromium, а не согласие на отклик.
Dry-run и отдельное явное подтверждение пользователя перед боевым `apply`
остаются обязательными.

## Шаг 1 — проверь готовность

```bash
hhru whoami
hhru list-resumes
```

Если сессия невалидна — `login` (интерактивный, требует пользователя). Если
резюме нет в конфиге — скажи пользователю заполнить `resume_url` в
`data/config.yaml`.

## Шаг 2 — изучи форму отклика (probe, READ)

Для конкретной вакансии — диагностический дамп формы без отправки:

```bash
hhru probe --vacancy-id <id>
```

`probe` ничего не отправляет на hh.ru (submit не кликается). Полезен, чтобы
проверить селекторы формы и AI-письмо до боевого отклика.

## Шаг 3 — сухой прогон (dry-run, обязательно)

```bash
hhru apply --resume <id> --dry-run --limit 5
```

`--dry-run` показывает план откликов **без действия** на hh.ru. Покажи
пользователю, на какие вакансии бот откликнется, и получи подтверждение.

**Важно:** dry-run-отклики тоже пишутся в локальную историю и считаются
«уже откликались» — боевой запуск на Шаге 4 пропустит именно те вакансии,
что были показаны в плане Шага 3, и подберёт другие кандидаты (или ни одного,
если подходящих вакансий больше нет). Это не баг, а дедупликация по дизайну —
предупреди пользователя, что боевой список может отличаться от dry-run-плана.

## Шаг 4 — боевой отклик (только после подтверждения)

```bash
hhru apply --resume <id> --limit 5
```

Боевой запуск реально отправляет отклики. **Не запускай без явного
подтверждения пользователя** после показа dry-run-плана. Уважай дневные лимиты
и троттлинг — не запускай повторно чаще, чем позволяет бот.

## Правила

- **Никаких эмодзи.** Вывод CLI — только текст и ASCII-таблицы.
- **Не обходи троттлинг/лимиты** и не запускай `apply` в фоне/скрыто.
- **Не используй `page.request.*` и внутренние API hh.ru** — только команды бота.
- Если `apply` упал на конкретной вакансии — это штатно (селектор/анти-фрод),
  не паникуй и не повторяй боевой запуск без разбора.
