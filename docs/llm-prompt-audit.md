# Аудит LLM-промптов: что реально уходит внешнему провайдеру (#1025)

Read-only аудит всех точек входа LLM по факту кода (класс #997/#998/#1005).
Методология — аудит #1007 и фикс #1005: утверждения привязаны к файл:строка,
источник контекста проверен по коду построения промпта, а не по замыслу.

Единый транспорт — `ai/llm_client.py::LLMClient.chat` (`src/hhru_bot/ai/llm_client.py:73`):
hhru не передаёт ключи/endpoint override, маршрут решает Hermes-цепочка. Все
вызовы `chat()` в проекте перечислены ниже; иных точек отправки данных в LLM
нет (проверено grep по `\.chat(` по `src/hhru_bot`).

## Итоги по чек-листу ишью

1. **Источник контекста.** Случаев класса #998 («литералы i18n/JSON-состояния
   страницы в промпте») по коду НЕ найдено: ни одна точка не отправляет
   `body.inner_text()`/outerHTML. После #1005 оба DOM-контекста (skills,
   languages) скоуплены до подтверждённых карточек/секций; остальные
   page-производные контексты — точечные чтения отдельных контролов
   (`vacancy_refresh.py:87`, `read_position`, `extract_questions`,
   `open_about_editor`).
2. **Ложные улики.** Случаев класса #1005 («модель видит поля, которых нет на
   целевой форме») не найдено: контексты скоуплены до целевой формы/секции
   (см. таблицу). Срез `[:12000]` в skills/languages применяется ПОСЛЕ
   скоупинга — полезное не вытесняется мусором (чек-лист п.5 закрыт).
3. **Приватность** — см. явный список ниже. Телефон/email/ФИО/паспортные
   данные в LLM-промпты не попадают ни в одной точке; единственный
   denylist-паттерн (`external_forms/detect.py:22`) страхует имена ключей.
4. **Инъекция из страницы.** Недоверенный текст (описание вакансии, тексты
   вопросов/опций, сообщение рекрутера) входит в промпты без явного
   разграничения «данные vs инструкции». Смягчения уже в коде: строго
   парсируемый JSON-выход во всех классификаторах/планах, выбор только из
   переданных списков (роли `:157`, шаблоны `answerer.py:218`, ключи
   `detect.py:253`). Осознанно принятый риск остаётся в free-text выходах
   (письмо, ответ рекрутеру, «Обо мне») — заведено фоллоу-ишью #1026.
5. **Объём.** Бюджеты на месте: reject/style 4000 симв. (`feedback.py:5`),
   rationale 240 (`scoring/vacancy.py:106`), max_tokens у всех вызовов задан
   или безопасен; единственный неограниченный строковый контекст — полное
   описание вакансии в письме (`ai/letters.py:164-166`) — это целевые данные,
   не мусор; отмечено в #1026 как сопутствующее.

## Приватность: персональные поля, уходящие провайдеру

Общее: `LLMClient` не передаёт ключей/метаданных аккаунта; hh.ru-сессия,
cookie и история в промпты не входят ни в одной точке.

| Точка | Персональные данные в промпте | Источник |
|---|---|---|
| 1 scoring | summary, skills, desired_role кандидата; причины прошлых отказов | конфиг (ai_profile), локальная история |
| 2 letters | summary, skills, highlights, desired_role; тексты прошлых писем (few-shot); отредактированные фрагменты писем | конфиг, локальная история |
| 3 questions | summary, skills, desired_role | конфиг |
| 4-7 classifier-пути | ТОЛЬКО имена полей/шаблонов; значения — нет | — |
| 6 contextual | instruction и examples шаблона (могут содержать личные факты — заданы пользователем намеренно) | конфиг/questionnaire history |
| 8 reply | нет данных кандидата (только вакансия + сообщение рекрутера) | — |
| 9-10 roles | нет (title — аргумент команды) | — |
| 11 adaptive | полная карьерная история: компании, должности, периоды, описания, проекты, навыки | конфиг (CandidateFacts) |
| 12 position | summary, skills, highlights, desired_role | конфиг |
| 13 experience | --career текст; существующие записи опыта (компания/должность/даты/обязанности) | CLI, страница своего резюме |
| 14 education | source-текст пользователя; текущие записи образования | CLI, страница своего резюме |
| 15 about | существующий текст «Обо мне»; profile-поля | своё резюме, конфиг |
| 16-17 skills/languages | текст собственных карточек резюме/языков | страница своего резюме |
| 18 sections | profile-поля; --context текст | конфиг, CLI |

Во всех случаях это данные самого кандидата, необходимые для задачи
(генерация/скоринг под его профиль), заданные им же в конфиге/CLI. Третьи
лица: единственный недоверенный внешний текст — вакансия/вопросы/сообщение
рекрутера, персональных полей в нём не запрашивается.
