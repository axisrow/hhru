# Ручной чеклист live-канала (#1164, этап 2 эпика #588)

Браузерное e2e в CI не строится: протокол, сценарии и транспорт канала
покрыты unit- и интеграционными тестами на фейковом WS-клиенте
(`tests/test_live_protocol.py`, `tests/test_bump_live.py`,
`tests/test_live_serve.py`, `tests/test_live_integration.py`). Живой контур
проверяется этим чеклистом. Боевые шаги выполняет только владелец аккаунта.

## 0. Подготовка

- [ ] Расширение hhru-live загружено в Chrome (README, раздел «Live-канал:
      установка расширения hhru-live»).
- [ ] Chrome открыт на вкладке hh.ru (для шага 2 — на `/applicant/resumes`).
- [ ] `./scripts/run.sh live-doctor` — все строки `[OK]` (сервер, подключение,
      версия протокола, allowlist, permissions).

## 1. Живое чтение — read-only, безопасно

Порядок критичен: MV3 service worker расширения подключается к каналу при
старте браузера и засыпает навсегда, если сервер в это окно не слушал
(живой факт 2026-09-20). Тест сам поднимает канал на 8765 — живой
`live-serve` останови; Chrome (пере)запусти ПОСЛЕ старта теста, например
`./scripts/run_extension_chrome.sh https://hh.ru/applicant/resumes`.

- [ ] `HHRU_LIVE_CONFIG=data/config.yaml pytest -m live_read tests/live/ -q -s`
      — `[OK]`, в выводе видны URL/title вкладки hh.ru и ответ `check_element`.
- [ ] План без мутаций: `./scripts/run.sh bump-live --resume <имя> --dry-run`
      — `[OK] <имя> поднято` (команда не печатает отдельной пометки dry-run);
      настоящий признак сухого прогона — кнопка поднятия осталась на странице.

## 2. Боевой bump-live (мутация своего аккаунта)

- [ ] `./scripts/run.sh bump-live --resume <имя>` — `[OK] <имя> поднято`; на
      странице кнопка сменилась disabled-хинтом «поднимать рано».
- [ ] Действие в истории: `action='bump'`, статус `success` в `data/history.db`
      (таблица `actions`), кулдаун 4ч соблюдается повторным запуском
      («Пропуск: рано поднимать»).

## 3. Боевой apply — только авторизованный запуск владельца

Submit отклика не автоматизируется: боевой `apply` запускает вручную
владелец, канал на этот шаг не влияет (отклик через живую вкладку появится
отдельной задачей S4, #1162 — тогда в этот раздел добавится свой пункт).

- [ ] Сухой прогон плана: `./scripts/run.sh apply --resume <имя> --dry-run --limit 5`.
- [ ] Владелец запускает боевой прогон: `./scripts/run.sh apply --resume <имя> --limit 5`.
- [ ] В выводе нет `[FAIL]`/`uncertain`; отклики видны в `responses` и в
      переговорах hh.ru.
